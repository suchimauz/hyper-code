## Context

The models stack (`src/models/`) has a provider SDK, transports (direct, SOCKS, SSH tunnel) exposed as `conn.fetch`, per-model disabling, a persistent model cache and a native `codex` provider (`$modelProvider_codex.ts`, `codexAuth`, `codexLogin`). Claude subscriptions exist only in the legacy path: `src/llm/*AnthropicOAuth*` (PKCE login, process-local pending flows, optional loopback callback on :53692), `llm.claudeFetch`, `llm.streamAnthropic`, `llm.compactAnthropic`, and usage via `/api/oauth/usage`. That code is keyed by credential slots, not by models connections, and its requests do not go through `conn.fetch`.

## Goals / Non-Goals

**Goals:**
- A built-in `claude` provider equal in shape to `codex`: login, tokens, models, usage, stream, compact — all through `conn.fetch`.
- Reuse pure helpers from `src/llm` through `ctx.fns` without changing them.
- Make the login panel flow-aware so future providers can pick device-code or authorization-code.

**Non-Goals:**
- Routing agents through models connections; migrating or removing legacy Claude accounts.
- API-key Anthropic access (custom provider covers it); reading `claude` CLI credential files.

## Decisions

1. **Same OAuth parameters as the working legacy flow.** The authorization URL is built exactly like `llm.startAnthropicOAuth`: constants from `llm.anthropicOAuthConstants` (client id, `https://claude.ai/oauth/authorize`, token URL `https://platform.claude.com/v1/oauth/token`, redirect `http://localhost:53692/callback`, scopes), `code=true`, PKCE S256 and a random state. The browser then redirects to the loopback callback. When MauzCode runs on the owner's machine, an optional loopback listener on that port completes login automatically; if the port is busy (for example a legacy login is pending) or MauzCode is remote, the listener is skipped and the owner pastes the callback URL from the address bar (the page fails to load, but the URL holds `code` and `state`). Parsing reuses `llm.parseAnthropicAuthorizationInput` (full URL, `code#state` or bare code). The token exchange sends the same `redirect_uri`, `state` and `code_verifier` and goes through `conn.fetch`. The browser leg never touches the transport, only the exchange does.
2. **`claudeLogin` mirrors `codexLogin`** with ops `start | status | submit | cancel`. Flows are process-local (lost on restart), keyed by connection, 10-minute expiry, one exchange attempt. `LoginFlow` gets `kind: "device-code" | "authorization-code"`; `userCode` becomes optional and `authorizationUrl` is added. Public result never includes verifier/code.
3. **`claudeAuth` mirrors `codexAuth`** (ops `status | token | store | markLogin | clear`): one encrypted secret per connection (`models/<id>.claude-auth`), compare-and-swap revision, single-flight refresh map. Expiry = `expires_in - 5 min` like `llm.exchangeAnthropicOAuth`. Refresh follows `llm.getAnthropicOAuthToken`: write `refreshUncertain: true` (CAS) before sending, clear it with the new tokens; a lost/invalid response → `OAUTH_OUTCOME_UNKNOWN`, no retry, login required; a stored uncertain flag fails fast after restart. The OAuth constants (client id, token URL, scopes) come from `llm.anthropicOAuthConstants`; the token endpoint is called via `conn.fetch`. Alternative — reuse `llm.exchangeAnthropicOAuth` — rejected because it uses its own fetch/proxy binding and slot storage.
4. **Client identity in one helper.** A provider-local `headers(ctx, conn, token, { compact })` builds bearer auth, `anthropic-version: 2023-06-01`, betas (`claude-code-20250219,oauth-2025-04-20,fine-grained-tool-streaming-2025-05-14,interleaved-thinking-2025-05-14`, overridable by `CLAUDE_CODE_ANTHROPIC_BETA`, plus `compact-2026-09-04` for compaction or a replayed compaction block), `user-agent: claude-cli/<version> (external, sdk-cli)` (overridable by `CLAUDE_CODE_USER_AGENT`), `x-app: cli`, `anthropic-dangerous-direct-browser-access: true`, `x-client-request-id: <uuid>`. Version = `config.clientVersion` or `llm.claudeCodeCliVersion({})`. Usage/profile requests carry only bearer, content type and user agent, as in `llm.refreshUsage`.
4a. **System prompt exactly as legacy.** Streaming follows `agent.buildLlmRequest` for `claude-code`/`anthropic-oauth`: `system` is only the identity line (anti-fraud check); instructions (leading identity line stripped) become `[user: instructions, assistant: "Understood. Ready to act."]` before the transcript. Compaction follows `llm.compactAnthropic`: `system: [{identity}, {instructions}]`. No new behaviour; the provider is a port of the legacy wire code onto the SDK.
4b. **Endpoint allow-list.** All provider traffic goes through one `claudeRequest(conn, url, init)` that checks the https method/URL pair against the five allowed destinations (same table as `llm.claudeFetch`) before calling `conn.fetch`; refusal is `PROXY_CONFIG` with `requestSent:false`.
4c. **Body.** `max_tokens: 16384`, `stream: true`, tools as given. Thinking via `llm.resolveReasoningEffort` exactly as `llm.streamAnthropic`: `auto` → nothing; effort → adaptive + `output_config.effort` (xhigh→max); `off` → `disabled`, omitted for `(opus|sonnet)-5`. Cache markers: last block of `messages[1]` (bootstrap ack) and of `messages[cacheableMessageCount+1]` tail, as in `streamAnthropic`; this needs `StreamRequest.cacheableMessageCount` (SDK delta).
5. **Streaming** converts with `llm.toAnthropicMessages`, parses SSE with `llm.parseSSE`, and ports the event handling of `llm.streamAnthropic`: `message_start`/`message_delta` usage (prompt = input + cache read + cache creation; `message_delta` wins), `content_block_start` tool slots, text/thinking/`input_json_delta`, stop mapping, `__unparsed` tool args, `error` events → `classifyError`, missing `message_stop` → retryable `PROXY_CONNECTION_LOST`, malformed JSON → failure (connections always have `noFallback` semantics: no silent direct retry). On success, unified rate-limit headers are recorded as connection usage (missing header ≠ 0%).
5a. **Errors** go through `llm.classifyError({ provider: "anthropic-oauth", kind: "subscription", status, body, headers })` so quota vs. throttling and reset parsing stay identical; 401/403 additionally call `claudeAuth markLogin`.
6. **Compaction** is a port of `llm.compactAnthropic`: non-streaming POST, betas `claude-code-20250219,oauth-2025-04-20,compact-2026-09-04`, `max_tokens` default 32000, `compaction: { type: "summarize" }` with focus wrapped into the handoff prompt, block taken from `content`, usage from `usage.iterations[type=compaction]`, empty block → error with stop reason. Reimplemented in the provider because the legacy function resolves legacy endpoints; `models.CompactRequest` gains `focus` and `maxTokens`.
7. **Models from code, no API call**: like the legacy path (`llm.listModels`, the `claudeModels` array), the subscription has no account-specific model catalogue, so `listModels` returns a static list of Claude model ids kept in the provider file and never touches the network. Availability still depends on the plan; an unsupported model fails clearly at inference. The connection test checks login with `GET /api/oauth/usage` instead of a models request.
8. **Usage**: `GET /api/oauth/usage`, map `five_hour` and `seven_day` (`utilization` → usedPercent, `resets_at` → resetAt); plan from `GET /api/oauth/profile` `organization.organization_type` (claude_max/pro/team/enterprise), failure tolerated. Per-model weekly windows are out of scope (legacy does not read them).

## Risks / Trade-offs

- [Anthropic changes OAuth client rules, betas or the identity check] → constants and betas stay overridable through the same env variables as the legacy path; tests pin the request shape.
- [Remote MauzCode cannot receive the loopback redirect] → the owner pastes the callback URL; same fallback as the legacy flow.
- [Port 53692 shared with the legacy flow] → the listener is best-effort; a busy port falls back to paste without failing login.
- [Process-local flows lost on restart] → the owner simply starts login again; same as codex.
- [Duplicate logic with legacy `src/llm`] → accepted for isolation; the legacy path will be retired in a later change once agents route through models connections.
