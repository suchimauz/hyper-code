# Retired badge adapters and Codex reset contract

Source audit after 464b1d3c found three remaining shell-only HTML refresh routes. Removed `/mentions/badge`, `/ui/gap-count`, `/ui/agent/:id/wake-timer`, their exclusive `mentions.badge`, `ui.gapBadge`, `ui.wakeTimer` renderers, and the orphan mentions/live and ui/gap-count scripts. No current source loaded those scripts; the renderers had only those route consumers (plus retired-renderer tests).

Preserved mention counting/list/read behavior and `/api/v1/agents` mention data, the global mentions menu, flow refreshCount/cache/cron/events and all wake scheduling/domain APIs. This is adapter cleanup, **not full visual parity**: the current React shell has no global gaps badge, legacy mention toast, or standalone wake countdown. Domain capabilities remain available; no replacement visual surface is claimed.

`POST /llms/codex/reset` now returns no-store JSON rather than HTML. The third-wave source adds the native `CodexAccountReset` control. The retained endpoint requires owner access under the existing auth/legacy-local policy, same origin, cookie-bound `X-CSRF-Token`, JSON, `confirmed: true`, an explicit `account`, optional `creditId`, and a stable 16–128 character alphanumeric/underscore/hyphen `idempotencyKey` reused on retries. It returns `{outcome, windowsReset}` and refreshes usage/account topics. Legacy form posts cannot redeem credits. The native control uses explicit confirmation and the JSON contract; an authenticated caller's boolean is not a separate approval authority. Final integrated verification remains pending.

Validation: mocked reset tests exercise JSON results, retry identity, auth/role/CSRF/origin and confirmation rejection without any real redemption. Flow aggregate tests remain. Deleted-renderer tests were removed; mention integration assertions now check retained per-agent domain counts. Route reload removes all three retired routes; helpers explicitly unloaded. Declarative route files are not runtime functions, so runtime.docs.validate rejects their names; loadRoutes is their reload mechanism. No server restart, credential action, commit or push.
