# Hyper-code2 Desktop (минимальный клиент)

Одна кодовая база Electron для Windows и macOS. Это оболочка **существующего** HTTP/HTTPS-сервера: Bun/Postgres внутри приложения не запускаются. При первом запуске укажите адрес, например `https://hyper.example.com` или `http://192.168.1.10:3000`. Доступ к серверу/VPN должен уже работать на компьютере.

## Почему Electron

Для минимального клиента выбран Electron: одинаковый Chromium на обеих платформах, штатные постоянные браузерные профили и готовая упаковка NSIS/DMG, без Rust и различий системных WebView. Цена — размер дистрибутива и расход памяти выше, чем у Tauri. Оболочка — отдельный пакет; основной Bun-проект, его зависимости и runtime-функции не меняются. Electron использует собственный Node.js в главном процессе; Bun здесь используется для установки, тестов и команд сборки, а не вместо Electron.

## Запуск разработчика

Нужны Bun и Node.js LTS (для инструментов упаковки). На Linux для запуска окна дополнительно нужны графическая сессия и системные библиотеки Electron; Linux-пакет пока не настроен. Не запускайте с `--no-sandbox` или от root.

```sh
cd desktop
bun install --frozen-lockfile
bun run dev
```

Установка скачает Electron под текущую платформу; это существенный объём. `trustedDependencies` разрешает его штатный postinstall. Если политика вашей установки запрещает lifecycle-скрипты, явно разрешите postinstall Electron; не отключайте проверки сертификатов. При разработке следите за обновлениями безопасности Electron и обновляйте версию вместе с lockfile.

## Что работает

- Ввод и сохранение URL; автоматическое подключение при следующем запуске.
- Полноценное окно серверного интерфейса.
- Меню **Сервер → Сменить сервер…** (`Ctrl+,` / `Cmd+,`).
- **Повторить подключение** (`Ctrl+R` / `Cmd+R`) и кнопка повтора при ошибке.
- До первой успешной загрузки ошибки DNS/сети/TLS, HTTP 4xx/5xx, падение renderer и таймаут 30 секунд возвращают окно подключения. После загрузки HTTP-ошибки отдельных страниц (включая 401/403/404/500) остаются в серверном окне: исходная страница ошибки или входа не подменяется, профиль и сервер не сбрасываются. Сетевые ошибки/TLS и падение renderer после загрузки показывают предупреждение с повтором, без возврата к настройке сервера.
- **Вид → Назад** (`Alt+←`) и **Повторить страницу** (`Ctrl+Shift+R` / `Cmd+Shift+R`) помогают вернуться с ошибочной страницы; **Сервер → Повторить подключение** заново открывает сохранённый адрес. Ошибки API внутри страницы обрабатывает сам веб-интерфейс.
- Исправления оболочки не обновляют уже установленный `.exe`/`.app`: для них нужно пересобрать и установить новый NSIS/DMG-пакет; обновления только серверного кода недостаточно.
- Адрес хранится в `server.json` внутри `app.getPath('userData')`; cookies/localStorage/IndexedDB — в штатном постоянном Chromium-профиле, отдельно для каждого origin (протокол + хост + порт). Повторный вход зависит от срока действия и политики сессии сервера: session-only cookies не превращаются самодельно в постоянные. Hyper auth штатно выдаёт cookie с `Max-Age`.

Пароли/токены оболочка не извлекает и не записывает отдельно. Выход выполняется средствами веб-интерфейса. Смена сервера **не удаляет** предыдущую сессию; для полного локального сброса закройте приложение и удалите его каталог userData. В обычной установке это `%APPDATA%/Hyper-code2` на Windows и `~/Library/Application Support/Hyper-code2` на macOS (в dev имя каталога может отличаться).

## Границы безопасности и ограничения

- Удалённый интерфейс без preload и Node.js, `contextIsolation`, `sandbox`, `webSecurity` включены; webview запрещён. IPC настройки доступен только главному frame локального окна с проверкой отправителя.
- Локальное окно имеет строгий CSP и ограниченный bridge, не отдающий файловые/процессные API.
- Сохраняются только HTTP/HTTPS-адреса без credentials, query и fragment: не вставляйте URL с секретами. HTTP разрешён для внутренней сети, но **не шифрует трафик**. Для недоверенной сети нужен HTTPS или защищённый VPN.
- Проверка TLS не отключается; самоподписанный сертификат без доверия ОС вызовет ошибку, кнопки обхода нет.
- Навигация главного окна остаётся в выбранном origin. Переходы на другие origin и новые окна предлагают открыть HTTP/HTTPS-ссылку в системном браузере, только после подтверждения. `file:`, `javascript:`, произвольные custom protocols не передаются ОС. Новые окна внутри Electron не создаются.
- Авторизация, требующая popup, внешнего OAuth-перехода с возвратом в приложение или custom protocol, может не работать: браузер не делится сессией с оболочкой. Используйте поддерживаемый сервером вход в том же origin. Это ограничение минимальной версии.
- Запросы разрешений (камера, микрофон, геолокация, уведомления и т. п.) и скачивания блокируются. Такие сценарии, PDF/export-загрузки и голосовой ввод потребуют отдельного разрешённого UX. Веб-содержимое остаётся сетевым приложением, не офлайн-копией.
- Не изменяется CSP сервера и не блокируются все сторонние подресурсы/iframe: их политику определяет сервер. Подключайтесь только к доверенному Hyper-серверу. Для локальных данных действуют защита профиля ОС/Chromium и права пользователя; отдельное шифрование оболочкой не реализовано.

## Трей и завершение

Крестик окна подключения и серверного окна скрывает окно, но оставляет приложение в Windows tray / macOS menu bar. Сессия и загруженный интерфейс остаются в памяти. Клик по иконке либо **Показать окно** восстанавливает окно (в том числе свёрнутое). Повторный запуск не создаёт второй клиент: он возвращает окно уже запущенного экземпляра. macOS Dock также восстанавливает скрытое окно.

**Выйти** в меню трея или приложения и `Cmd+Q` действительно завершают процесс. Обработчики закрытия не удерживают приложение при явном выходе и системном shutdown/logout (Windows session-end и macOS powerMonitor shutdown). Если иконку трея не удалось создать, запуск завершается с ошибкой, вместо недоступного фонового процесса.

## Иконки

Оригинальная геометрическая **H** на индиговом фоне создана для этого клиента, без внешних изображений. Ресурсы в `assets/` входят в приложение: `icon.ico` (16–256 px) для Windows, `icon.icns` (16–1024 px) для macOS, `icon.png` для окна и `tray.png` для Windows tray. Отдельные чёрные с прозрачностью `trayTemplate.png` (18 px) и `trayTemplate@2x.png` (36 px) помечены Electron как template для системной окраски macOS menu bar.

Воспроизводимая генерация: `cd desktop && bun run icons`. Генератор `generate-icons.cjs` использует только встроенные Node/Bun API, без конвертеров, загрузок или системных пакетов; после изменения запустите `bun run test`. electron-builder использует явные `win.icon` / `mac.icon`. Проверка форматов не заменяет визуальную проверку на настоящих ОС.

## Сборка Windows

Рекомендуется нативная Windows-машина/CI runner (x64), Bun и Node.js LTS:

```sh
cd desktop
bun install --frozen-lockfile
bun run test
bun run check
bun run build:win
```

Результат — NSIS `.exe` в `desktop/dist/`. На Linux кросс-сборка Windows может потребовать Wine и дополнительные инструменты, здесь не проверена и не является основным поддерживаемым путём.

### Медленное скачивание Electron (Linux/WSL и Windows)

`bun run build:win` сначала выполняет `bun run prefetch:win`: скачивает официальный Windows x64 ZIP закреплённой версии Electron через тот же `@electron/get`, который использует electron-builder, с `downloadOptions.timeout.request = 3600000` (1 час на HTTP-запрос). SHA256 проверяется по официальному `SHASUMS256.txt`, TLS не отключается. Затем electron-builder берёт ZIP из того же стандартного кэша (на Linux обычно `~/.cache/electron`, учитывается `XDG_CACHE_HOME`). Выполняйте обе стадии под одним пользователем и с одинаковым окружением; не включайте режим обхода кэша electron-builder. Переменные зеркал и подмены версии/имени файла prefetch отвергает, а не направляет скачивание на сторонний сервер.

При ошибке `Timeout awaiting 'request' for 600000ms` просто повторите `bun run build:win`. Можно сначала выполнить только `bun run prefetch:win`, а сборку запустить позднее. Частично скачанный ZIP не считается готовым кэшем; продолжение с прежнего процента не гарантируется.

Причина отдельного шага: electron-builder **26.15.3** задаёт 10-минутный request timeout в `app-builder-lib/out/util/electronGet.js`; его конфигурационная схема не разрешает `electronDownload.downloadOptions`. Поэтому это не выдуманная настройка builder и не patch `node_modules`, а поддерживаемый API `@electron/get` для предварительной загрузки с проверкой checksum. Настройка относится только к Electron Windows x64 при сборке, не к `bun install`/postinstall, macOS, NSIS/Wine или остальным инструментам упаковки. Полную Windows-сборку и длительное скачивание автоматические тесты не выполняют.

## Сборка macOS

Собирать на macOS с Bun, Node.js LTS и Xcode Command Line Tools:

```sh
cd desktop
bun install --frozen-lockfile
bun run test
bun run check
bun run build:mac
```

Получаются отдельные `.dmg` для Apple Silicon (`arm64`) и Intel (`x64`) в `desktop/dist/`, не universal binary. macOS-подпись и нотариализация требуют macOS и Apple Developer credentials. Минимальная поддерживаемая версия ОС определяется закреплённым Electron, проверьте её перед распространением; старые ОС этим проектом отдельно не поддерживаются.

### Подпись и распространение

Команды выше не публикуют релизы. Без сертификатов Windows-сборка будет неподписанной, возможны предупреждения SmartScreen. Для нормального распространения настройте Windows code signing через защищённые переменные CI/electron-builder. На macOS без Developer ID и нотариализации Gatekeeper может блокировать запуск; ad-hoc подпись не заменяет доверенную подпись. Настройте штатные signing/notarization options electron-builder и секреты CI; не записывайте ключи или пароли в репозиторий. Auto-update, release pipeline и публикация в этой версии не реализованы.

## Проверки и их границы

Без скачивания Electron:

```sh
cd desktop
bun run test
bun run check
# Только разрешение зависимостей/lockfile, без runtime и install scripts:
bun install --lockfile-only --ignore-scripts
```

Проверено в Linux-окружении: тесты URL/навигационной политики, lifecycle на mock Electron (закрытие/восстановление, single-instance, явный выход, shutdown), валидация контейнеров ICO/ICNS и декодирование PNG с CRC, статическая сборка JS Bun (Electron external). Это не запуск Electron и не сборка установщика. Windows/macOS GUI, NSIS/DMG, подпись и реальные auth/session-сценарии здесь **не проверены**.

Перед выпуском на обеих платформах вручную проверьте: закрытие обоих типов окна в трей; восстановление кликом/меню, повторным запуском и macOS Dock (включая minimized); «Выйти»/Cmd+Q; logout/shutdown ОС без блокировки; иконки в установщике, Dock/taskbar и menu bar в светлой/тёмной теме; первый ввод URL; вход и сохранение сессии после полного выхода; смену сервера/возврат; недоступный адрес; неверный TLS; HTTP 500; внешний переход с отменой/подтверждением; отклонение `file:`/custom protocols; восстановление после обрыва сети; обычные Copy/Paste и доступность меню. Тесты политики не заменяют этот smoke-test.
